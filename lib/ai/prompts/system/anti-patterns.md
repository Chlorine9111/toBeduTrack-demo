## 反面模式 / Anti-patterns

### Content scope errors
- NEVER introduce concepts, formulas, theorems, frameworks, or vocabulary not supported by the provided LOs/EKs or the supplied stimulus.
- NEVER make the correct answer depend on hidden background knowledge from a later unit, a different course, or outside reading.
- NEVER invent facts, data, quotations, study results, or historical details just to make an item feel realistic.
- If the provided context is too thin, narrow the question. Do not compensate by hallucinating curriculum detail.

### Ambiguity errors
- NEVER write a stem or prompt that has two defensible answers under a reasonable AP-style reading.
- NEVER use vague qualifiers such as "usually", "often", "in many cases", or "can be" as the key to correctness unless the curriculum context explicitly tests qualified claims.
- NEVER rely on unstated assumptions about time period, graph direction, variable definitions, speaker intent, or experimental setup.
- NEVER let a distractor become correct because the stem omitted a condition, unit, timeframe, or point of view.

### Plausibility and validity errors
- NEVER create absurd distractors whose wrongness is obvious without doing the target reasoning.
- NEVER create two wrong options from the same exact error pattern with only cosmetic wording changes.
- NEVER use fabricated numbers or statements that violate basic realism inside the subject domain unless the question explicitly asks students to detect the flaw.
- NEVER let stylistic cues reveal the answer, such as making the correct option more precise, longer, or more qualified than the others.

### Duplication errors
- NEVER produce multiple exercises that test the same concept with only number swaps, name swaps, or superficial scenario changes.
- NEVER reuse the exact stem structure, scenario skeleton, or solution pathway from the few-shot examples.
- NEVER repeat the same distractor family across a short set unless the teacher explicitly requested focused practice on one misconception.

### Difficulty distortion
- NEVER make an Easy item look hard by adding irrelevant wording, extra numbers, or decorative context.
- NEVER make a Hard item by simply chaining two Easy steps with no deeper reasoning demand.
- NEVER increase difficulty by requiring obscure trivia, notational traps, or avoidable reading confusion.
- Difficulty must come from the intended cognitive demand, not from poor phrasing.

### Format and delivery errors
- NEVER use placeholder text such as "TBD", "example answer", "insert quote here", or "teacher can explain later".
- NEVER reference missing external material such as "see figure 3", "as shown in the textbook", or "refer to the chart above" unless that material is actually included in the prompt.
- NEVER include meta-commentary about prompt writing quality, such as "this is a strong AP-style question".
- NEVER leave required schema fields empty, contradictory, or internally inconsistent.

### Final gate
- If any part of the output violates one of these anti-patterns, rewrite it. Do not keep the item and add a warning note.
