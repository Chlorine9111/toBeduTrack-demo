### 学科适配：计算机科学（AP Computer Science A / AP Computer Science Principles）

以下规则覆盖计算机科学课程，在通用 Block 质量要求基础上追加执行。

**example block**
- Start from a concrete code snippet, trace table, algorithm description, data set, network diagram, or computing-innovation scenario. Never ask students to reason about "some program" in the abstract.
- Structure steps as a computing reasoning chain: "identify inputs and state -> trace control flow or data transformation -> apply the relevant abstraction, algorithm, or system rule -> determine output, bug, efficiency, or impact -> justify with exact lines, conditions, or data behavior."
- Use exact technical vocabulary: variable, parameter, return value, iteration, Boolean expression, list index, object state, algorithm, protocol, data abstraction, or bias in data. Do not substitute with vague phrases like "the code changes somehow."
- If the scenario is AP CSP style, connect the computing concept to data, networks, impact, or abstraction. If it is AP CSA style, anchor it to code behavior, class design, or program tracing.

**paragraph block**
- Teacher: display a short program, pseudocode block, state table, or system diagram; pause at a key line or step and ask students to predict what happens next.
- Student: trace variables line by line, complete a table of intermediate values, debug a faulty condition, or explain why one algorithm is preferable under the stated constraint.
- The activity must specify the exact input, the execution path to inspect, and the output or side effect students must explain.

**definition block**
- Use a three-layer structure: 1) formal computing definition 2) a tiny concrete example in code, pseudocode, or system behavior 3) a contrast with a nearby term such as parameter vs argument, algorithm vs program, or array vs ArrayList.
- When the concept concerns data or systems, state what is stored, transmitted, transformed, or abstracted, not just a slogan-level description.
- When the concept concerns code, include the observable behavior: output, updated state, returned value, or runtime effect.

**quiz block**
- Base the item on a visible artifact: code, pseudocode, data table, execution trace, protocol scenario, or computing-innovation claim.
- Target tracing, algorithmic reasoning, debugging, data representation, abstraction, or impact analysis rather than syntax trivia alone.
- The explanation must point to the exact line, condition, iteration, data transformation, or system rule that determines the answer.

**关键原则**
Computer science is only "specific" when the reasoning is traceable. Every explanation should name the concrete input/state, the rule being applied, and the resulting behavior or impact.
