# ADR-0003: 保留独立微信内容生产工作台

## 状态
Accepted

## 背景
项目除了教学内容生成，还承担公众号内容生产与排版场景，且已有独立 API 与编辑器组件。

## 备选方案
1. 完全移除微信模块
2. 与教学工作台完全融合为单一路径
3. 保留独立入口并共享基础能力（当前实现）

## 决策
保留微信模块独立工作台，编辑器入口固定为 `/main/wechat-editor`。本决策最初将根路径 `/` 用作跳转；面试 Demo 已用公开 Landing Page 取代该行为。旧 `/api/wechat/generate` 冻结为兼容提示接口，不再承担生成逻辑。

## 决策理由
- 现有代码已具备完整链路：文档/图片输入、AI 生成、模板渲染、导出复制。
- 与教学模块共享基础设施，但交互形态不同，独立维护更清晰。

## 影响
- 正向影响：产品面收口为单一入口，减少双入口和双实现带来的维护成本。
- 负向影响：仍需维护少量共享底层能力（如文档解析、视觉分析），不能简单整目录删除。
- 后续动作：继续统一模型接入与错误返回风格，并逐步清理未再被引用的旧实现。
